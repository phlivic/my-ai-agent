# New Update Ver 0.2

## Purpose

Version 0.2 introduces a real preference system that becomes the single source of truth for personalization across the project.

This update replaces the earlier placeholder preference behavior with a persistent profile system that:

- stores preferences on the backend
- uses a stable internal scope key instead of any user-defined name
- powers the recommendation workflow
- can be edited from the frontend
- can be updated automatically from user messages when unlocked

User-defined names remain a conversational feature only. They are not used as profile keys, storage keys, or identity keys.

## Main Product Change

The chat UI will gain a new `💗` button placed to the right of the existing `💡` button.

Expected behavior:

- `💡` stays responsible for recommendation prefill
- `💗` opens a preferences panel
- when the panel opens, the chat area shifts left
- a new panel appears on the right side
- the panel contains preference content, editing controls, and a lock button

The current stable internal profile key remains:

- `scopeKey = "default-user"`

This is the only profile key in v0.2. Later versions can replace it with a real account-based identifier without changing the preference API shape.

## Design Principles

1. Preferences must have one single source of truth.
2. Placeholder preference fields from earlier code must stop affecting behavior.
3. Internal persistence must never depend on a user-defined display name.
4. Automatic preference updates must use only user messages.
5. AI replies must never be used as preference evidence.
6. Automatic updates are allowed to be more aggressive in this project than in a production-safe system.
7. Deletion is allowed in auto-update mode, but only through structured rules and bounded updates.

## Source Of Truth

The old placeholder preference field inside the chat agent state must no longer be used for recommendation logic or future profile logic.

In practice:

- `AgentState.preferences` is deprecated
- recommendation features must read only the new profile object
- the frontend panel must read and write only the new profile object
- automatic inference must write only the new profile object

If the old field still exists temporarily for compatibility, it must not drive behavior anymore.

## New Preference Profile Model

The new persistent profile object should be the only personalization model used by the system.

Suggested shape:

```ts
type PreferenceProfile = {
  scopeKey: string;
  locked: boolean;
  displayName: string;
  interests: string[];
  keywords: string[];
  regions: string[];
  languages: string[];
  sources: string[];
  avoid: string[];
  updatedAt: string;
  lastUpdatedBy: "manual" | "inferred";
  recentChanges: PreferenceChange[];
};

type PreferenceChange = {
  type: "add" | "remove";
  field: "interests" | "keywords" | "regions" | "languages" | "sources" | "avoid";
  value: string;
  reason: string;
  at: string;
  by: "manual" | "inferred";
};
```

### Field meaning

- `scopeKey`: stable internal profile key
- `locked`: whether automatic updates are allowed
- `displayName`: user-facing conversational name only
- `interests`: human-readable topics the user cares about
- `keywords`: AI-generated or user-approved search terms used by recommendation logic
- `regions`: geographic focus
- `languages`: preferred content languages
- `sources`: source preferences or source restrictions
- `avoid`: themes or categories the user prefers to avoid
- `updatedAt`: last profile write time
- `lastUpdatedBy`: whether the last write came from manual editing or inference
- `recentChanges`: audit-friendly change list for UI display

## Frontend UX Plan

### Toolbar Layout

The composer action area should become:

- left: `💡` recommendation button
- right: `💗` preferences button

### Panel Behavior

When the user clicks `💗`:

- the chat card compresses to the left
- a right-side preference panel appears
- the panel can be closed by clicking `💗` again

Desktop behavior:

- split layout, chat on the left, panel on the right

Mobile behavior:

- stacked layout or slide-over panel

### Panel Content

The panel should show:

1. Header
   - title: `Preferences`
   - lock control: `🔒 Locked` or `🔓 Adaptive`

2. Display name
   - editable user-facing name
   - affects conversation tone only
   - does not affect persistence keys

3. Interests
   - tag-based editing UI

4. AI-generated keywords
   - tag-based editing UI
   - generated and maintained with AI support

5. Regions
   - tag-based editing UI

6. Languages
   - tag-based editing UI

7. Sources
   - tag-based editing UI

8. Avoid
   - tag-based editing UI

9. Recent updates
   - short list of recent inferred or manual changes

10. Mode description
   - `Locked: only manual edits apply.`
   - `Adaptive: preferences may change based on your messages.`

## Lock Behavior

### Locked mode

When `locked = true`:

- the panel can still be edited manually
- recommendation uses saved preferences
- chat does not trigger automatic preference updates

### Adaptive mode

When `locked = false`:

- the panel can still be edited manually
- recommendation uses saved preferences
- backend may update preferences after user messages
- only user messages are valid evidence

## Backend API Plan

The preference system should follow the same stable scope model already used elsewhere.

### Read profile

`GET /api/profile/preferences`

Headers:

```http
x-user-scope: default-user
```

Response:

```json
{
  "scopeKey": "default-user",
  "profile": {
    "scopeKey": "default-user",
    "locked": false,
    "displayName": "Guest",
    "interests": ["AI", "Startups"],
    "keywords": ["agents", "funding"],
    "regions": ["US"],
    "languages": ["English"],
    "sources": [],
    "avoid": ["celebrity news"],
    "updatedAt": "2026-03-02T12:00:00.000Z",
    "lastUpdatedBy": "manual",
    "recentChanges": []
  }
}
```

### Manual patch

`PATCH /api/profile/preferences`

Request body:

```json
{
  "displayName": "Shaoyang",
  "interests": ["AI", "Policy"],
  "keywords": ["agents", "regulation"],
  "regions": ["US"],
  "languages": ["English"],
  "sources": [],
  "avoid": ["celebrity news"]
}
```

Behavior:

- normalizes casing and whitespace
- deduplicates values
- writes a complete updated profile
- records change entries in `recentChanges`
- sets `lastUpdatedBy = "manual"`

### Lock toggle

`PATCH /api/profile/preferences/lock`

Request body:

```json
{
  "locked": true
}
```
